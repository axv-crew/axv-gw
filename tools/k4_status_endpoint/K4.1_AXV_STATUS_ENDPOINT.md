# K4.1 - AXV Status Endpoint Documentation

## 📋 Przegląd

Endpoint `/axv/status` stanowi **Single Source of Truth** dla stanu wszystkich komponentów systemu AXV. Jest zaprojektowany do:

- 🔍 Monitoringu (Grafana, Prometheus)
- 📊 Status Page (publicznego lub wewnętrznego)
- 🤖 Automatyzacji w n8n
- 🚨 Alertingu

## 🎯 Cel

Jeden, zunifikowany endpoint zwracający stan całego ekosystemu AXV:
- `api` - stan axv_api
- `gateway` - stan axv_gw (reverse proxy)
- `n8n` - stan workflow engine
- `rag` - stan Atlas EDGE RAG
- `nodes` - lista nodów klastra

## 📡 API Reference

### Endpoint

```
GET /axv/status
```

### Response Schema

```json
{
  "now": 1762714225,
  "ok": true,
  "version": "0.1.9",
  "overall_status": null,
  "status": {
    "api": "ok",
    "gateway": "ok",
    "n8n": "ok",
    "rag": "unknown"
  },
  "nodes": [
    {
      "id": "aster",
      "role": "edge",
      "host": "asus",
      "ok": true,
      "status": "ok",
      "age_s": 12,
      "last_seen": 1762714225
    }
  ]
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `now` | int | Unix timestamp (sekundy) |
| `ok` | bool | `true` jeśli wszystkie komponenty OK/unknown |
| `version` | string | Wersja API |
| `overall_status` | string\|null | `"degraded"` gdy ok=true ale są problemy |
| `status` | object | Status poszczególnych komponentów |
| `nodes` | array | Lista nodów klastra |

### Status Values

Każdy komponent w `status.*` może mieć jedną z wartości:

| Value | Znaczenie | Przykład |
|-------|-----------|----------|
| `ok` | Działa poprawnie | HTTP 200, szybka odpowiedź |
| `degraded` | Działa z problemami | Timeout, wolna odpowiedź, błędy 4xx |
| `down` | Nie odpowiada | Connection refused, 5xx errors |
| `unknown` | Brak danych | Komponent nie ma healthcheck endpoint |

### Overall Status Logic

```python
if any(status == "down"):
    ok = False
    overall_status = None
elif any(status == "degraded"):
    ok = True
    overall_status = "degraded"
else:
    ok = True
    overall_status = None
```

**Strategia:**
- `ok=false` → **critical outage**, coś jest down
- `ok=true` + `overall_status="degraded"` → **system działa**, ale z problemami
- `ok=true` + `overall_status=null` → **wszystko OK**

### 2. Concurrent Execution

Wszystkie health checks wykonują się **równolegle** dla lepszej performance:

```python
api, gw, n8n, rag, nodes = await asyncio.gather(
    check_api_health(),
    check_gateway_health(),
    check_n8n_health(),
    check_rag_health(),
    get_nodes_status(),
    return_exceptions=True  # graceful degradation
)
```

### 3. Timeout Policy

- **Default timeout:** 2 sekundy na każdy health check
- **Fail-fast:** lepiej zwrócić "degraded" niż czekać długo
- **No blocking:** żadne długie operacje (DB queries, file I/O)

### 4. Error Handling

```python
try:
    response = await client.get(url, timeout=2.0)
    if response.status_code == 200:
        return "ok"
    elif response.status_code >= 500:
        return "down"
    else:
        return "degraded"
except TimeoutException:
    return "degraded"  # działa, ale wolno
except ConnectError:
    return "down"      # nie odpowiada
```

## 📊 Integration Examples

### 1. Status Page

```html
<!-- Simple status page -->
<script>
async function updateStatus() {
  const res = await fetch('/axv/status');
  const data = await res.json();
  
  document.getElementById('overall').className = 
    data.ok ? 'status-ok' : 'status-down';
  
  if (data.overall_status === 'degraded') {
    document.getElementById('overall').className = 'status-degraded';
  }
  
  // Update component badges
  Object.entries(data.status).forEach(([key, value]) => {
    document.getElementById(key).textContent = value;
    document.getElementById(key).className = `badge-${value}`;
  });
}

setInterval(updateStatus, 30000); // co 30s
</script>
```

### 4. Prometheus Exporter

```python
from prometheus_client import Gauge

# Define metrics
status_ok = Gauge('axv_status_ok', 'Overall AXV status')
component_status = Gauge(
    'axv_component_status',
    'Component status (1=ok, 0.5=degraded, 0=down, -1=unknown)',
    ['component']
)

@app.on_event("startup")
async def setup_metrics():
    async def collect_metrics():
        while True:
            res = await client.get("/axv/status")
            data = res.json()
            
            status_ok.set(1 if data['ok'] else 0)
            
            for comp, status in data['status'].items():
                value = {
                    'ok': 1,
                    'degraded': 0.5,
                    'down': 0,
                    'unknown': -1
                }[status]
                component_status.labels(component=comp).set(value)
            
            await asyncio.sleep(15)
    
    asyncio.create_task(collect_metrics())
```

## 🔍 Troubleshooting

### Problem: Gateway shows "down"

**Diagnoza:**
```bash
# Check if gateway is running
curl http://127.0.0.1:8000/axv/healthz

# Check logs
docker logs axv_gw -f
```

**Rozwiązanie:**
- Sprawdź czy gateway działa
- Zweryfikuj URL w konfiguracji
- Sprawdź firewall/network

### Problem: Wszystkie komponenty "unknown"

**Przyczyna:** Brak skonfigurowanych URL-i healthz

**Rozwiązanie:**
```python
# Configure proper URLs
config = {
    "gateway_healthz_url": "http://actual-gateway:8000/axv/healthz",
    "n8n_healthz_url": "http://n8n.axv.life/healthz",
}
configure_status_endpoint(app, config)
```

### Problem: Endpoint bardzo wolny

**Diagnoza:**
- Sprawdź logi - może być timeout na healthcheck
- Zweryfikuj czy wszystkie zależności odpowiadają

**Rozwiązanie:**
```python
# Zmniejsz timeout (domyślnie 2s)
config = {"healthcheck_timeout": 1.0}
```
